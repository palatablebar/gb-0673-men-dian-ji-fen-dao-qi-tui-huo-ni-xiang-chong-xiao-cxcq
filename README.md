# 门店积分到期与退货逆向冲销

给连锁零售会员运营专员使用。消费先用最早到期批次；退款按原消费分配逆向恢复，已过期部分不得复活。

八个业务模块：事件采信、权益规则、积分归批、消费到期、退货回拨、余额对账、期末归档、误发撤回。

```sh
docker compose up --build -d
docker compose exec -T app pytest -q
```

访问 http://localhost:18242 。启动直接载入现场脏批。切换干净样例、旧编码样例与误发撤回批可对照核验。会员00001两批积分100和80，消费120后退款30，其中20恢复、10已过期不恢复；再消费50后余额30。整批发放1580、余额1010、消费730、退款170、到期10，守恒可复核。

各模块页面对应 `/<模块英文名>`，各模块执行入口为 `POST /api/<模块英文名>`，不传参即可独立演示。完整运行 `POST /api/runs` 支持 `dataset`（dirty/clean/legacy/misissue）、`csv_text` 与 `overrides` 参数。批次历史 `GET /api/runs`，详情 `GET /api/runs/{run_id}`。

同输入与规则版本生成相同批号，只保留一条批次。复核入口 `POST /api/runs/{run_id}/review` 提交当前 `revision`，陈旧提交409。归档包只有一个下载入口 `GET /api/export/{run_id}`，含证据和运行摘要。原始隔离在页面同屏显示。

SQLite使用命名卷，容器重启后保留历史。要重建演示可在Compose中改用新的卷名称，保留旧卷。

源码在 `app/`，样例在 `sample_data/`，测试在 `tests/`；定义见 `docs/DATA-DICTIONARY.md`，模块和边界测试对应关系见 `docs/DEPTH.md`。输入上限2MB，属于离线复核工具。

采信页支持上传或粘贴CSV。完整源字节与参数随批次持久化，跨页通过run_id读取同一结果。`POST /api/runs/{run_id}/rerun` 读取该批不可变输入快照重新计算，规则未变时批号不变。切换另一示例则创建或复用另一批次。

## 误发批次撤回（M8）

误发的月底奖励积分以规则名 `月底奖励` 标记（见 `sample_data/misissue.csv` 与 `context-misissue.json`），撤回只作用于该规则的发放批次，`常规` 营销权益与其他批次一律不动。

裁决先做反事实重放：剔除误发发放后重放该户全部历史消费与退货。若全部仍成立，则**整批撤销**（误发额全额撤回，含已耗用部分一并核销）；若有消费/退货失去支撑，则**部分撤回**，仅收回误发批次当前尚可追回的余额，已耗用或到期部分记为不可追、不向会员追偿，绝不使余额为负。原始 EARN/SPEND/REFUND 记录不修改、不覆盖，撤回只在流水追加 `REVOKE` 条目，历史全程可追查。

发布与安全语义：

- 页面 `/withdrawal` 列出每户误发额、尚可追回、撤回额、撤回前后余额与发布状态。
- 发布 `POST /api/runs/{run_id}/withdrawals/publish`，支持 `revision`（乐观锁，陈旧返回409）与 `idempotency_key`（重复执行返回同一撤回单，不重复扣减）。
- 发布在事务内备份旧 run 结果到撤回单；任一步失败整体回滚，撤回单标记 `发布失败`，旧版本余额原样保留。
- 回滚 `POST /api/withdrawals/{id}/rollback` 用发布前备份恢复旧余额，回滚本身幂等。
- 撤回后余额经户内与总额两级对账确认，凭证随 `GET /api/export/{run_id}` 归档。
